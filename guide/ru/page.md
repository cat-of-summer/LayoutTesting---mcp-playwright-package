# Фаза 11. Страница целиком

Когда все блоки готовы — прогон по странице, на каждом брейкпоинте.

## Порядок

```
audit                         → самый дешёвый первый шаг, сводка по всем проверкам
figma_compare(кадр страницы)  → отдельный прогон на каждый брейкпоинт
layout_audit                  → скролл, наложения, обрезанный текст, тач-таргеты
interaction_audit             → в сессии с animations: "allow"
a11y_axe + a11y_pa11y         → наборы правил разные, ловят разное
validate_html
```

`figma_compare` открывает свою сессию шириной кадра — сравнивать десктопный макет с мобильной
вёрсткой бессмысленно.

## Про `heightNote` и попиксельное сравнение

Пока высота страницы не сошлась с кадром, всё ниже расхождения смещено целиком.

На fluid-вёрстке с подменённым шрифтом расхождение копится по 30–80px на секцию и к низу длинной
страницы доходит до сотен пикселей. Это **ожидаемое** следствие подмены шрифта, а не дефект.

Практическое следствие: **`mode: pixel` на длинной fluid-странице почти бесполезен** —
`diffPercentage` там показывает четверть страницы при полностью корректной вёрстке. Работают
`semantic` и `paint`: они сопоставляют по содержимому и по месту с поправкой на сдвиг.

## Про валидатор

`validate_html` сам выносит из общего счёта то, чего валидатор не знает: встроенный современный
CSS — в поле `css`, новые атрибуты платформы (`popover`, `inert`, `fetchpriority`, `xlink` в
инлайновом SVG) — в поле `known`. В `total` они не входят.

Список `known` именной, а не выведенный из спецификации, и отсюда его слабость: опечатка в таком
атрибуте спрячется вместе с правильными. Увидеть всё как есть — `strict: true`.

## Про контраст

Если низкий контраст идёт из палитры макета — **не чинить молча**, а вынести человеку. Менять
брендовые цвета агент не вправе.

## Гейт страницы

Ноль находок по `documentOverflow`, `overlaps`, `clippedText`, `brokenImages`,
`imagesWithoutDimensions`, `tinyTargets`; пустой `silent` у `interaction_audit`. Остальное — с
обоснованием.
