# Фаза 11. Страница целиком

Когда все блоки готовы — прогон по странице, на каждом кадре макета и на каждой ширине между ними.

## Чек-лист

ВХОД: все блоки прошли гейт фазы 10 в обоих кадрах.
ШАГИ:
  1. audit — сводка по всем проверкам.
  2. figma_compare(кадр страницы) — на каждый кадр: semantic и sections: true; coverage без пробелов.
  3. layout_audit(widths: из figma_sync.widths.suggested) — скролл, наложения, обрезки, тач-таргеты на каждой ширине.
  4. interaction_audit в живой сессии; browser_goto с frames — стартовая анимация.
  5. a11y_axe + a11y_pa11y; validate_html (ignore — только для соглашений библиотек).
  6. Отчёт «готово» — только после 2 и 4.

## Порядок

```
audit                                          → самый дешёвый первый шаг, сводка по всем проверкам
figma_compare(кадр, mode: "semantic")          → отдельный прогон на каждый кадр
figma_compare(кадр, sections: true)            → попиксельно по каждой секции кадра
layout_audit(widths: [...])                    → скролл, наложения, обрезанный текст, тач-таргеты — на каждой ширине
interaction_audit                              → в живой сессии
browser_goto(url, frames: {count, stepMs})     → первые кадры после навигации: intro
a11y_axe + a11y_pa11y                          → наборы правил разные, ловят разное
validate_html
```

`figma_compare` открывает свою сессию шириной кадра — сравнивать десктопный макет с мобильной
вёрсткой бессмысленно.

## Ширины между кадрами

Кадров два — ширин для прогона минимум пять: макетные, 768, 1024, 1280 и минимальная между
макетными. `layout_audit` с `widths` прогоняет одну сессию по всем и сводит в таблицу; на каждой
ширине читать `documentOverflow` и `boxOverflow`.

> На 1440 и 380 переполнений не было. На 1068 фиксированный слайдер с фиксированной колонкой
> не помещались в контейнер — колонка уходила за экран. Промежуточные ширины не открывали ни разу.

## Про `heightNote` и попиксельное сравнение

Пока высота страницы не сошлась с кадром, всё ниже расхождения смещено целиком.

На fluid-вёрстке с подменённым шрифтом расхождение копится по 30–80px на секцию и к низу длинной
страницы доходит до сотен пикселей. Это **ожидаемое** следствие подмены шрифта, а не дефект.

Практическое следствие: **`mode: pixel` по всей длинной странице бесполезен** — `diffPercentage`
там показывает четверть страницы при полностью корректной вёрстке. Работают `semantic` и `paint`
(сопоставление по содержимому и по месту с поправкой на сдвиг) и `sections: true`: каждая секция
сверяется картинкой отдельно, со своей поправкой на сдвиг, и накопленное смещение её не
затрагивает. «Пиксели не работают на длинной странице» — не повод не сверять картинкой вовсе.

## Про валидатор

`validate_html` сам выносит из общего счёта то, чего валидатор не знает: встроенный современный
CSS — в поле `css`, новые атрибуты платформы (`popover`, `inert`, `fetchpriority`, `xlink` в
инлайновом SVG) — в поле `known`. В `total` они не входят.

Соглашения библиотек проекта (пользовательские теги, атрибуты компонентов) — в `ignore`, чтобы
шум не заслонял настоящие ошибки; отфильтрованное показывается отдельно в `ignored`, и его
объём — часть отчёта, а не то, что исчезло.

Список `known` именной, а не выведенный из спецификации, и отсюда его слабость: опечатка в таком
атрибуте спрячется вместе с правильными. Увидеть всё как есть — `strict: true`.

## Про контраст

Если низкий контраст идёт из палитры макета — **не чинить молча**, а вынести человеку. Менять
брендовые цвета агент не вправе.

## Гейт страницы

Ноль находок по `documentOverflow`, `overlaps`, `clippedText`, `brokenImages`,
`imagesWithoutDimensions`, `tinyTargets` на каждой ширине; пустой `silent` у
`interaction_audit`; `coverage` у `figma_compare` каждого кадра без пробелов; intro просмотрен
по кадрам. Остальное — с обоснованием.
