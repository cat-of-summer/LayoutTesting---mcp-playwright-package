# Фаза 6. Микро-ТЗ постранично

Всё собранное о странице - в один короткий файл: по нему верстают и по нему принимают.

## Чек-лист

ВХОД: поведение описано, ответы человека получены.
ШАГИ:
  1. docs/design/pages/<страница>.md по шаблону; на лендинге - раздел в README.
  2. По каждой секции: id узлов, компоненты из UI-кита, тексты, ассеты, поведение.
  3. Требования из comments.md и таблицы поведения - пунктами "- [ ]" в свою секцию.
  4. Тексты - в данные, один источник на все брейкпоинты; пробелы-переносы из Figma вычистить скриптом.
  5. Заглушки списков опознаны; компонент работает при 0, 1 и N элементах.
  6. Раздел "Принятые решения" заведён.

## 6.1 Шаблон

```markdown
---
page: Главная
route: /
frames: { desktop: 280:6100, mobile: 280:7900 }
---
## hero
Узлы: 280:6101 / 280:7901. Кит: Button, Tag. Ассеты: hero.webp.
- [ ] Заголовок в 2 строки на 1440, прописными
- [ ] Фото появляется первым, затем подпись (motion_frames 280:6105)
- [ ] На таче первый тап показывает подпись, второй ведёт на /about

## Принятые решения
- Подсказка "листается" показывается один раз за сессию.
```

Микро-ТЗ - вход агента-верстальщика и чек-лист приёмки. Файл короткий: значения CSS в него не переписываются, они берутся из узла по id. Текст файла передаётся в `page_ready` параметром `checklist`.

## 6.2 Тексты в данные, не в разметку

Один источник на все брейкпоинты, плюс из него собирается сабсет шрифта.

## 6.3 Figma отдаёт переносы строк пробелами

В китайском и японском это рвёт слова посреди слова: `而地缘政 治压力` вместо `而地缘政治压力`.
Вычищать пробелы между иероглифами скриптом — в одном проекте таких оказалось 59. В кириллице и
латинице то же самое, но заметно меньше.

Полные тексты берутся из `figma_spec` (раздел `text`) или `figma_inspect` с `mode: "text"`:
остальные режимы режут строки многоточием.

## 6.4 Количество элементов в макете ≠ количество в жизни

Три карточки новостей и пагинация «01 … 10» — это заглушка ленты из тридцати. Компонент должен
работать при любом количестве, включая ноль и один. Проверяется это `layout_stress` со сценарием
`lists`.

## 6.5 Состояние - не данные

Раскрытая первая карточка слайдера в макете — это показанное состояние (`hover`, активный слайд),
а не признак «у этой карточки есть суммы». Данные о суммах — у всех карточек; раскрытие —
класс состояния (`swiper-slide-active`, `:hover`). Подменять поведение содержимым данных ради
совпадения высоты секции нельзя: высота сойдётся, поведение — нет.

## Гейт фазы

На каждую страницу есть микро-ТЗ: секции с id, компонентами и ассетами, все требования пунктами, заглушки опознаны, тексты вынесены.
