# Фаза 2. Инвентаризация блоков и связей

Что на экране есть и что оно делает.

## 2.1 Структура

```
figma_structure(кадр, depth: 2..4)
```

Отдаёт дерево «как в вёрстке», а не дамп слоёв, и помечает места, где вёрстка по слоям была бы
неверной:

| Пометка | Что значит |
|---|---|
| `{overlay: поверх X — position: absolute}` | элемент лежит поверх, не в потоке |
| `{decor: выходит за край}` | псевдоэлемент или фон, не контент |
| `{background: фигура под всем содержимым}` | это фон контейнера, а не элемент |
| `reparented` | в слоях рядом, нарисованы внутри — в разметке дети |
| «группа не создаёт бокс» | обёртки в вёрстке быть не должно |

## 2.2 Полные тексты

```
figma_spec(узел) → раздел text
```

`outline` и `structure` режут длинные строки многоточием — об этом говорит `textsClipped`.

## 2.3 Связи и требования

```
figma_behavior(кадры)   → что с чем связано, с длительностями и easing
figma_comments(кадры)   → требования, которых нет в самом макете
```

`figma_behavior` группирует связи по цели: шесть одинаковых шевронов — один обработчик, а не
шесть.

> `figma_comments` не был вызван ни разу за проект — и это упущение. Половина требований живёт в
> комментариях и аннотациях Dev Mode: «поправить отступ», «здесь будет форма», «этот блок пока не
> делаем».

## 2.4 Опознать типовые элементы

Выписать: шапка, подвал, меню (десктоп и мобильное), формы, слайдеры, аккордеоны, модалки, табы,
хлебные крошки, сайдбар, выпадающие списки, пагинация, тултипы, тосты. Для каждого — назначение
и связи.

Связи вида «модалка успеха показывается после отправки формы» берутся из `figma_behavior`; если
связи нет — это вопрос человеку, а не повод придумать.

## Гейт фазы

Для каждого интерактивного элемента известно, что он делает. Всё неописанное помечено
`unconfirmed` и ушло вопросом.
