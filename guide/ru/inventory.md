# Фаза 2. Инвентаризация блоков и связей

Что на экране есть, что оно делает и что про него написано в комментариях.

## Чек-лист

ВХОД: карта кадров подтверждена.
ШАГИ:
  1. figma_structure(кадр, depth: 2..4) — дерево «как в вёрстке», пометки overlay/decor/background/reparented.
  2. figma_spec(узел) → text — полные тексты (outline режет многоточием).
  3. figma_comments(кадры) — требования из комментариев и аннотаций; нет REST — блокер, вопрос человеку.
  4. figma_behavior(кадры) — связи; каждый notSynced → figma_sync и разобрать.
  5. Список типовых элементов с назначением; всё неописанное — в unconfirmed и вопросом.

## 2.1 Структура

```
figma_structure(кадр, depth: 2..4)
```

Отдаёт дерево «как в вёрстке», а не дамп слоёв, и помечает места, где вёрстка по слоям была бы
неверной:

| Пометка | Что значит |
|---|---|
| `{overlay: поверх X — position: absolute}` | элемент лежит поверх, не в потоке |
| `{decor: выходит за край}` | псевдоэлемент или фон, не контент |
| `{background: фигура под всем содержимым}` | это фон контейнера, а не элемент |
| `reparented` | в слоях рядом, нарисованы внутри — в разметке дети |
| «группа не создаёт бокс» | обёртки в вёрстке быть не должно |

## 2.2 Полные тексты

```
figma_spec(узел) → раздел text
```

`outline` и `structure` режут длинные строки многоточием — об этом говорит `textsClipped`.

## 2.3 Связи и требования

```
figma_comments(кадры)   → требования, которых нет в самом макете
figma_behavior(кадры)   → что с чем связано, с длительностями и easing
```

**Комментарии читаются до вёрстки.** Это единственный канал, где живут требования вроде «здесь
JS-анимация по ховеру, как на сайте-эталоне» или «этот блок пока не делаем». Инструмент работает
только через REST; нет токена — это блокер, о котором спрашивают человека, а не данность.

> На одном лендинге `figma_comments` не вызывали ни разу — hover трёх блоков придумали сами, а в
> комментарии стоял эталон с готового сайта. На другом — «поправить отступ», «здесь будет
> форма» тоже жили только в комментариях.

`figma_behavior` группирует связи по цели: шесть одинаковых шевронов — один обработчик, а не
шесть. Цели, которых нет в снимке, лежат в `notSynced` — каждую снять `figma_sync` и разобрать:
hover-вариант компонента-ссылки остался в `notSynced`, и hover придумали вместо того, чтобы
взять.

## 2.4 Опознать типовые элементы

Выписать: шапка, подвал, меню (десктоп и мобильное), формы, слайдеры, аккордеоны, модалки, табы,
хлебные крошки, сайдбар, выпадающие списки, пагинация, тултипы, тосты. Для каждого — назначение
и связи.

Связи вида «модалка успеха показывается после отправки формы» берутся из `figma_behavior`; если
связи нет — это вопрос человеку, а не повод придумать.

## Гейт фазы

Комментарии прочитаны или их отсутствие согласовано; для каждого интерактивного элемента
известно, что он делает; `notSynced` пуст; всё неописанное помечено `unconfirmed` и ушло
вопросом.
