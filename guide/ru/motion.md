# Фаза 8. Анимации и состояния

Направление перехода, его параметры, стартовые состояния и полный список состояний каждого элемента.

## Чек-лист

ВХОД: ответы человека получены, в том числе про объём анимаций.
ШАГИ:
  1. figma_behavior(кадры) — триггер, длительность, easing; каждый notSynced → figma_sync.
  2. figma_spec(обе точки перехода) — краска «откуда» и «куда», направление по обеим.
  3. Стартовые состояния intro — в CSS под классом .js, а не только в JS.
  4. Hover перекрывающихся элементов — без смены z-index; hover, которого нет в макете, — сказать в отчёте.
  5. Для каждого интерактивного элемента — список состояний: hover, focus-visible, active, disabled, error, loading, empty.
  6. Всё уважает prefers-reduced-motion.

## 8.1 Снять параметры

```
figma_behavior                        → триггер, длительность, easing, группировка
figma_sync(цели связей из notSynced)  → во что переключается вариант
figma_spec(цель)                      → краска целевого состояния
```

Связь даёт «откуда → куда». Чтобы понять направление, снять **оба** состояния.

> **Как здесь ошибаются.** Связь вела от дефолта хиро к варианту с `rgba(0,0,0,0.4)`. Была
> посмотрена только цель — и сделан вывод, что вуаль уходит. В дефолте было `{op0.2}` поверх
> `rgba(0,0,0,0.1)` — почти прозрачная плёнка, и вуаль **приходит**. Направление восстановилось,
> только когда сняли оба состояния.

`notSynced` не оставляют: hover-вариант компонента-ссылки остался неснятым, и hover придумали
(тень + сдвиг) вместо того, который нарисован.

## 8.2 Стартовое состояние — в CSS, не только в JS

Стартовая анимация, чьи начальные значения выставляет только скрипт (`gsap.set`,
`clip-path`, `scale`, `autoAlpha: 0`), показывает **финальный кадр** между рендером HTML и
запуском модуля: `type="module"` отложен, а страница уже нарисована. В замороженной сессии это
невидимо, а `browser_goto` дожидается загрузки — первые кадры проходят до первого снимка.

Правильно — стартовые состояния в CSS под классом, который ставит инлайн-скрипт в `<head>` до
отрисовки body:

```scss
.js [data-hero-reveal] { clip-path: inset(-5% 100% -5% 0); }
.js [data-hero-stat]   { opacity: 0; visibility: hidden; }
```

Без JS класса нет — контент виден сразу. Проверять — `browser_goto` с `frames` в живой сессии:
серия снимков сразу после навигации.

## 8.3 Hover: не менять порядок наложения

Перекрывающиеся элементы (круги внахлёст, стопка карточек) при `:hover { z-index: … }` меняются
местами на границе двух элементов, и порядок дёргается. Масштаб и тень достаточны; порядок
наложения остаётся как в макете.

Hover, которого в макете нет, — решение агента, и оно проговаривается в отчёте: «активный круг —
не ссылка, hover намеренно отсутствует». Молчаливое решение неотличимо от забытого.

## 8.4 Состояния элементов

Отдельно выписать для каждого интерактивного элемента: `hover`, `focus-visible`, `active`,
`disabled`, `error`, состояние загрузки, пустое состояние. В макете это обычно варианты
компонента — берутся из `figma_components` и `figma_behavior`.

Пропущенное состояние заметить труднее всего: на макете его просто нет, и в сверке оно не
всплывёт.

## 8.5 Обязательное

Любая анимация уважает `prefers-reduced-motion`.

## Гейт фазы

Для каждой анимации известны триггер, обе точки, длительность и кривая; стартовые состояния
заданы CSS; для каждого элемента — список состояний; `notSynced` пуст.
