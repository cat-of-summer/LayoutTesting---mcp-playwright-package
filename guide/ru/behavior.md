# Фаза 5. Поведение и договорённости

Как страница ведёт себя во времени и под пальцем: снять из макета, а чего там нет - спросить до вёрстки.

## Чек-лист

ВХОД: UI-кит собран и сверен.
ШАГИ:
  1. figma_behavior(кадры, compact: true) - триггер, длительность, easing; blocking → figma_sync по его next.
  2. motion_frames(инстанс, fps) по каждой неочевидной анимации - кадры и числовые треки вместо догадки.
  3. figma_spec(обе точки перехода) - краска "откуда" и "куда", направление по обеим.
  4. Таблица поведения: скролл-сцены, hover на таче, подсказки "один раз", раскрытия, листаемые ряды, начальное состояние шапки.
  5. Вопросы человеку - только меняющие объём работы, с вариантами. Остальное решить самому и записать в "Принятые решения".
  6. Для каждого интерактивного элемента - состояния: hover, focus-visible, active, disabled, error, loading, empty. Стартовые состояния intro - в CSS под .js, всё уважает prefers-reduced-motion.

## 5.1 Чего нет в статичном кадре

На ТОПГАН агенты решили это сами и не спросили, и почти все замечания типа "не так работает" пришли отсюда. По каждой странице - строка на каждый пункт:

| Что | Что решить |
|---|---|
| Скролл-сцена | scrub, autoplay при входе или pin с прогрессом; разовая или повторяемая |
| Hover, меняющий содержимое | тач-вариант: первый тап - состояние, второй - ссылка |
| Подсказка, онбординг | условие показа, "один раз" на что: сессию, устройство, аккаунт |
| Раскрытие | что двигается, что стоит на месте; сброс при смене таба |
| Обрезанный или листаемый ряд | свайп и признак того, что ряд листается |
| Оверлей, меню | что из шапки остаётся и во что превращается |
| Начальное состояние | как выглядит шапка до первого скролла |

## 5.2 Смотреть движение, а не описание

`figma_behavior` даёт "Smart Animate 700 ms ease-out", но не показывает, что едет. Траекторию спирали на ТОПГАН придумали, и ритм вышел чужим.

```
motion_frames(figma: <инстанс>, fps: 12)            → контакт-лист и треки: слой, свойство, значение в кадре
motion_frames(figma, steps: 4)                      → цепочка раскадровки подряд
motion_frames(figma, url, selector, triggerSelector) → та же анимация на странице и расхождения
```

Плеер показывает экраны прототипа, поэтому передавать надо инстанс со страницы макета, а не вариант из набора. Переход по таймауту плеер не снимет: для него остаются треки. Смотреть контакт-лист достаточно один раз на анимацию, дальше сверка идёт числами.

`figma_behavior` группирует связи по цели: шесть одинаковых шевронов — один обработчик, а не
шесть. Цели, которых нет в снимке, — блокирующая находка `blocking` в начале ответа, с готовым вызовом
`figma_sync` в `next`: снять и разобрать. Hover-вариант компонента-ссылки остался неснятым, и
hover придумали вместо того, чтобы взять.

## 5.3 Снять параметры

```
figma_behavior                        → триггер, длительность, easing, группировка
figma_sync(next из blocking)          → во что переключается вариант
figma_spec(цель)                      → краска целевого состояния
```

Связь даёт «откуда → куда». Чтобы понять направление, снять **оба** состояния.

> **Как здесь ошибаются.** Связь вела от дефолта хиро к варианту с `rgba(0,0,0,0.4)`. Была
> посмотрена только цель — и сделан вывод, что вуаль уходит. В дефолте было `{op0.2}` поверх
> `rgba(0,0,0,0.1)` — почти прозрачная плёнка, и вуаль **приходит**. Направление восстановилось,
> только когда сняли оба состояния.

`blocking` не оставляют: hover-вариант компонента-ссылки остался неснятым, и hover придумали
(тень + сдвиг) вместо того, который нарисован.

## 5.4 Стартовое состояние — в CSS, не только в JS

Стартовая анимация, чьи начальные значения выставляет только скрипт (`gsap.set`,
`clip-path`, `scale`, `autoAlpha: 0`), показывает **финальный кадр** между рендером HTML и
запуском модуля: `type="module"` отложен, а страница уже нарисована. В замороженной сессии это
невидимо, а `browser_goto` дожидается загрузки — первые кадры проходят до первого снимка.

Правильно — стартовые состояния в CSS под классом, который ставит инлайн-скрипт в `<head>` до
отрисовки body:

```scss
.js [data-hero-reveal] { clip-path: inset(-5% 100% -5% 0); }
.js [data-hero-stat]   { opacity: 0; visibility: hidden; }
```

Без JS класса нет — контент виден сразу. Проверять — `browser_goto` с `frames` в живой сессии:
серия снимков сразу после навигации.

## 5.5 Hover: не менять порядок наложения

Перекрывающиеся элементы (круги внахлёст, стопка карточек) при `:hover { z-index: … }` меняются
местами на границе двух элементов, и порядок дёргается. Масштаб и тень достаточны; порядок
наложения остаётся как в макете.

Hover, которого в макете нет, — решение агента, и оно проговаривается в отчёте: «активный круг —
не ссылка, hover намеренно отсутствует». Молчаливое решение неотличимо от забытого.

## 5.6 Состояния элементов

Отдельно выписать для каждого интерактивного элемента: `hover`, `focus-visible`, `active`,
`disabled`, `error`, состояние загрузки, пустое состояние. В макете это обычно варианты
компонента — берутся из `figma_components` и `figma_behavior`.

Пропущенное состояние заметить труднее всего: на макете его просто нет, и в сверке оно не
всплывёт.

## 5.7 Обязательное

Любая анимация уважает `prefers-reduced-motion`.

## 5.8 Что спросить

- **Шрифты** — есть ли файлы коммерческого, чем заменять.
- **Объём анимаций** — всё из прототипа, часть, ничего.
- **Заглушки** — языковые версии и разделы, которых нет в макете.
- **Адаптив между кадрами** — fluid `clamp()` или фиксированные состояния.
- **Данные** — сколько элементов в реальном списке.
- **Спорные места макета** — противоречия, `drift`, явные ошибки дизайнера.
- **Контраст из палитры** — если низкий контраст идёт из брендовых цветов, менять их агент не
  вправе. Это решение человека.

## 5.9 Как ставить вопрос

Формулировка не должна подталкивать к тому, что дешевле агенту. В мобильном кадре не было шапки,
а кадр начинался с отступа под неё — явный сигнал, что шапка есть где-то в файле. Её не искали,
а вопрос поставили как «статичные блоки без хедера (Recommended)» против «с выпадашками — укажи
node-id»; человек выбрал первое, потому что второе требовало работы от него. Шапка при этом
лежала в файле отдельным кадром. Правильно: сначала поиск (фаза 1), и только если не нашлось —
«шапки в файле не нашёл: где она, или верстать заглушку?» без рекомендации в пользу «не делать».

## 5.10 Чего не спрашивать

Того, что закрывается проверкой: прочитать код, выполнить запрос, посмотреть конфиг. Спрашивают
там, где ответ знает только человек: приоритеты, намерения, доступ, решения о рисках.

## 5.11 Решение - не молчание

Мелких вопросов на большом макете набираются десятки, и задавать все - тормоз. Человеку идут те, что меняют объём работы: шрифты, адаптив, карта, объём анимаций, маршруты, отход от модели фреймворка. Остальное агент решает в стилистике сайта и пишет строкой в раздел "Принятые решения" разбора страницы: человек видит все решения в одном месте и правит выборочно.

## Гейт фазы

Для каждой анимации известны триггер, обе точки, длительность и кривая; таблица поведения заполнена по каждой странице; ответы человека получены; стартовые состояния заданы CSS; для каждого элемента есть список состояний; `blocking` нет.
