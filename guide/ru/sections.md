# Фаза 2. Нарезка секций

Каждая страница режется на секции один раз: на этот реестр дальше ссылаются комментарии, UI-кит, микро-ТЗ и сверка.

## Чек-лист

ВХОД: карта кадров подтверждена.
ШАГИ:
  1. docs/design/README.md: страница, маршрут, id кадров desktop и mobile, служебные кадры и состояния.
  2. figma_structure(кадр, depth: 2..4) - секции страницы и пометки overlay/decor/background/reparented.
  3. Реестр секций: имя, id desktop, id mobile, общая или своя. Секция без пары на другой ширине - поиск в файле, потом вопрос.
  4. figma_spec(узел, sections: ["text"]) - полные тексты: outline режет многоточием.
  5. Типовые элементы: где повторяются и что из них уйдёт в UI-кит.

## 2.1 Реестр секций

Разбор живёт в файлах проекта, а не в голове агента: контекст за часы работы сжимается, агент может оборваться, а страниц бывает больше, чем помещается в одну сессию. На лендинге весь разбор - один файл `docs/design/README.md`. На сайте - он же как карта плюс `docs/design/pages/<страница>.md`.

```markdown
## Главная /
| Секция | desktop | mobile | Тип |
|---|---|---|---|
| hero | 280:6100 | 280:7900 | своя |
| cta-записаться | 280:6190 | 280:7990 | общая: Главная, Услуги |
```

Секция, которая повторяется на нескольких страницах, верстается один раз: это решается здесь, а не при вёрстке второй страницы.

## 2.2 Структура

```
figma_structure(кадр, depth: 2..4)
```

Отдаёт дерево «как в вёрстке», а не дамп слоёв, и помечает места, где вёрстка по слоям была бы
неверной:

| Пометка | Что значит |
|---|---|
| `{overlay: поверх X — position: absolute}` | элемент лежит поверх, не в потоке |
| `{decor: выходит за край}` | псевдоэлемент или фон, не контент |
| `{background: фигура под всем содержимым}` | это фон контейнера, а не элемент |
| `reparented` | в слоях рядом, нарисованы внутри — в разметке дети |
| «группа не создаёт бокс» | обёртки в вёрстке быть не должно |

## 2.3 Полные тексты

```
figma_spec(узел) → раздел text
```

`outline` и `structure` режут длинные строки многоточием — об этом говорит `textsClipped`.

## 2.4 Опознать типовые элементы

Выписать: шапка, подвал, меню (десктоп и мобильное), формы, слайдеры, аккордеоны, модалки, табы,
хлебные крошки, сайдбар, выпадающие списки, пагинация, тултипы, тосты. Для каждого — назначение
и связи.

Связи вида «модалка успеха показывается после отправки формы» берутся из `figma_behavior`; если
связи нет — это вопрос человеку, а не повод придумать.

## Гейт фазы

На каждую страницу есть реестр секций с id обеих ширин; типовые элементы выписаны; секция без пары найдена в файле или названа вопросом.
