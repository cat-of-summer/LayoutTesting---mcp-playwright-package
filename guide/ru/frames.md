# Фаза 1. Разведка макета

Какие кадры вообще верстать — и какие только выглядят кадрами, что обрезано родителем, что не кадр.

## Чек-лист

ВХОД: фаза 0 закрыта, есть все ссылки задачи.
ШАГИ:
  1. figma_sync(все ссылки одним вызовом) — сводка кадров, path каждого узла, widths.suggested.
  2. У каждого id из задачи — path: это кадр или дочерний узел? Дочерний → родитель в figma_inspect.
  3. figma_structure(канвас, depth: 1) + figma_export(kind: "render") — опознать глазами; parts: "children" у длинных кадров.
  4. Узлы с [clip] в outline — что обрезано родителем: clipped в ответе figma_export.
  5. Таблица кадр → ширина → что это → верстаем или нет; показать человеку.

## 1.1 Снять кадры

```
figma_sync(все ссылки задачи одним вызовом)
```

Один вызов на файл — дальше разбор идёт по снимку и в Figma не ходит. Лимит REST на Starter —
десять запросов в минуту, у места View/Collab двадцать в месяц.

В ответе у каждого кадра — `path` (где он лежит в файле) и, если снято два кадра разной ширины,
`widths.suggested`: ширины для прогонов фаз 10–12. Запишите их: «планшетного макета нет»
не значит «планшет не проверяем».

Ссылка без node-id отдаёт список страниц и кадров. Кадров на странице больше сотни — `page` и
`offset` в `figma_sync`, а не перебор соседних id.

## 1.2 Опознать кадры

```
figma_structure(канвас, depth: 1)                          → что лежит на холсте
figma_export(kind: "render", scale: 0.5)                   → опознать глазами
figma_export(длинный кадр, parts: "children")              → по одному дочернему фрейму на часть
```

Чего ожидать:

- **Ссылка из задачи может указывать не на кадр.** `node-id` вёл на весь канвас в 2678 узлов.
  В другой раз три «модалки» из задачи оказались одним `RECTANGLE` внутри сайдбара — это
  увидел бы `path`, а искали перебором соседних id.
- **Один экран бывает разложен на несколько кадров.** Мобильная версия жила в двух: `Mobile 1`
  (хиро…футер) и `Mobile` (секции, дорисованные позже). Свёрстан был бы только первый — половина
  страницы осталась бы без мобильной версии.
- **Часть экрана лежит в другом кадре или на другой странице.** Мобильный кадр начинался с
  отступа под шапку, а самой шапки в нём не было — она лежала отдельным кадром в том же файле.
  Агент её не нашёл и предложил верстать «без шапки». Пустое место с отступом — это поиск, а не
  вопрос: `figma_sync` без node-id даёт список страниц и кадров (`page`, `offset` — если их
  больше сотни), `figma_components` по снятым кадрам показывает инстансы шапки, и только если
  не нашлось нигде — вопрос человеку.
- **Рядом лежат служебные кадры.** `Перевод` — исходник текстов для переводчика. `Новые блоки` —
  секции, уже вмёрженные в основной макет. `блок 1` — хиро отдельно. Это не страницы.
- **Смещение за край родителя с `clip` — задумка.** Кнопка-вкладка шириной 137 лежала во
  фрейме той же ширины с `clip` на `x=92`: наружу торчат 45px — иконка, текст спрятан и
  выезжает по клику. Рендер `figma_export` делается **без обрезки родителем** и показал кнопку целиком;
  смещение прочли как небрежность и «исправили». Поле `clipped` в ответе экспорта теперь
  говорит, сколько видно в макете; при `[clip]` у родителя в outline — верить ему, а не рендеру.
- **Длинный мобильный кадр читается целиком.** Кадр в шесть тысяч точек порезался на 25
  частей; прочитаны 6, остальное додумано — оттуда половина мобильных ошибок. `parts: "children"` даёт по части
  на дочерний фрейм, и каждая часть подписана узлом. Если рендер выше рамки кадра
  (`oversized` в ответе), содержимое выходит за кадр, и в вёрстке это тоже увидят.

## 1.3 Составить карту

Таблица: кадр → ширина → что это (страница, состояние, черновик, справочный материал) →
верстаем или нет. Отдельной строкой — узлы, у которых видна только часть (`clipped`), и
элементы, которых в кадре нет, но которые подразумеваются (шапка, подвал, модалки): где они
найдены.

## Гейт фазы

Карта кадров показана человеку и подтверждена. Кадр, про который непонятно «макет это или
черновик», — вопрос человеку, а не решение агента.
