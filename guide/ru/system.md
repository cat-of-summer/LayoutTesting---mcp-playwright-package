# Фаза 4. Дизайн-система

Токены, компоненты, ассеты и шрифты - весь UI-кит до первой страницы.

## Чек-лист

ВХОД: секции нарезаны, комментарии разобраны.
ШАГИ:
  1. figma_tokens(все кадры) — палитра, unbound, clamp(); упал — сообщить человеку и идти по figma_spec css.
  2. figma_components(все кадры) — кластеры с модификаторами, drift, parallels (фиксированные высоты).
  3. figma_breakpoints(кадры одного экрана) — что меняется между ширинами, готовый clamp().
  4. Переменные и UI-кит заведены; ни одно значение из figma_tokens не попало в CSS без узла.
  5. UI-кит сверен со словарём фреймворка (фаза 0): кнопка-иконка — через его утилиту зоны клика, иконка — через маску, скрытое — через утилиту видимости.
  6. Ассеты: figma_spec(кадр) → assets и plan; figma_export(plan.svg, plan.image, compact: true); monochrome: true → color на обёртке; краска узла - в CSS.
  7. Шрифты: покрытие глифов нужного языка (fontkit hasGlyphForCodePoint). Нет файла или глифа - вопрос человеку, подмена согласована.
  8. Шкала между макетами: мобильная вёрстка на планшете не раздувается; вариант - вопрос человеку.
  9. UI-кит сверен на работающем dev-сервере до страниц: его ошибки размножаются.

## Словарь фреймворка

Фреймворк проекта уже решает часть задач UI-кита: зону клика у кнопки-иконки, маску иконки,
скрытие для глаз. Свой CSS рядом с его утилитой — вторая реализация, которая расходится с
первой.

> **Утилиту не применили.** Во фреймворке была утилита зоны клика для кнопок-иконок. Крестик
> модалки сверстали 15×15, бургер — 20×20, и зона нажатия у обоих была меньше 24px.

## 4.1 Токены

```
figma_tokens(все кадры)
```

Полезен тремя вещами:

- **частотность** — видно, что основное, а что разовое;
- **`unbound`** — сколько раз значение вбито литералом при живой переменной Figma; это и есть
  работа, которую выносят в токен;
- готовые **`clamp()`** по парам кадров разной ширины.

Токеном становится значение, привязанное к переменной Figma, встречающееся не один раз или уже
существующее в проекте. Разовый отступ токеном не становится. То, что меняется по варианту или
состоянию, — переменная компонента (`.btn{--btn-bg}` → `.btn--ghost{--btn-bg:…}`), а не новый
глобальный токен.

> **Главная ловушка.** `figma_tokens` — это словарь файла, а не свойства узла. Четыре бага подряд
> (линия 1px, полоса 10px, цвет `rgba(0,0,0,.8)`, тире 2px) — значения, взятые из частотной
> сводки «по смыслу». Все четыре мимо. См. правило 1 в разделе `rules`.

**Инструмент упал — это баг стенда, а не повод пропустить фазу.** Сказать человеку (с текстом
ошибки) и собрать палитру по `figma_spec` с `sections: ["css"]` для **каждого** блока, а не для
части. На одном лендинге `figma_tokens` падал, палитру собрали из `css` только у половины
блоков — цвет тире в списке подпунктов в итоге придумали.

**Цвет — по роли, а не по имени.** У каждого цвета `figma_tokens` отдаёт `roles` — где он стоит:
`state` — в вариантах-состояниях (Hover, Active, Selected), `tag` — в тегах и статусах; `stateColors` —
палитра состояний с долей, `roles` — строка-итог. «Загорается зелёным» дизайнер написал про
фирменный #E7EB70, которым горят все активные состояния кита, а агент взял токен green #81F989 —
он в макете стоит только у тега «Успешно». Цвет ховера, фокуса и выбранного берётся из
`stateColors`; придуманный ховер вне этой палитры `page_ready` и `lint_css` с `figma` отдают
блокером.

**Тема библиотеки — по её переменным, а не по догадке.** Datepicker, слайдер, селект темизируют
переменными библиотеки; после темизации — `lint_css` с `sessionId` в открытом состоянии виджета:
`unusedCustomProperty` с `didYouMean` — переменной с таким именем у библиотеки нет,
`libraryDefault` — переменная состояния (выбранная дата, диапазон) осталась по умолчанию.

## 4.2 Компоненты

```
figma_components(все кадры)
```

Сводит инстансы одного компонента в блок с модификаторами из свойств варианта. Непривязанные
блоки одинакового состава — тоже один блок: цвет, радиус, отступы и кегль становятся осями
модификаторов, а не поводом завести второй класс. Разовый элемент компонентом не делают.

`drift` — расхождения в пару пикселей или полтона внутри одного компонента. Это расхождение
**в макете**: сводят к одному значению, а не переносят в вёрстку.

`parallels` — то, что видно только на нескольких инстансах сразу: дочерний узел стоит на одном
`y` у всех, хотя сосед над ним разной высоты. Значит, у соседа **фиксированная высота**, а не
`hug`, — и в CSS это `height`/`min-height`, а не «от контента».

> У трёх карточек заголовок занимал 66px при любой длине текста, поэтому даты стояли на одной линии.
> В outline это `270x66 [h:hug]` — прочли `hug` и сделали высоту от контента; даты «поплыли».
> Один узел этого не покажет, три соседних — покажут.

## 4.3 Брейкпоинты

```
figma_breakpoints(кадры одного экрана разной ширины)
```

Показывает, что тот же элемент, что изменилось (кегли, отступы, направление раскладки), что
исчезло, чем заменено, где разошёлся порядок чтения. Линейно меняющиеся значения отдаёт готовым
`clamp()`.

Правило: mobile-first. Линейно меняющееся — `clamp()`, скачком — media-запрос. Замена элемента
(select на десктопе, иконка на мобильной) — два состояния одного блока, а не два блока.

Точка перелома **проверяется прогоном по ширинам** (`layout_stress`, сценарий `widths`), а не
назначается по числу из макета. Ширины — из `widths.suggested` в ответе `figma_sync`.

## 4.4 Инвентарь: что чем является

```
figma_spec(кадр) → раздел assets
```

Отвечает разом: какие узлы иконки, какие растр, каким нужен рендер, где дубли. `plan` — готовые
списки id для `figma_export`, дубли уже сведены. Запросов в Figma не тратит: считает по снимку.
У каждого `svg` стоит `color` — цвет заливки вектора; он понадобится в п. 4.2.

Перед выгрузкой — проверить, нет ли этих иконок и картинок **уже в проекте**. Экспорт стоит
запросов из лимита, а логотип и типовые пиктограммы обычно лежат в общих компонентах с прошлых
задач. Совпадения по классам и переменным проекта показывает `figma_components` и `figma_tokens`
с параметром `project`.

| В макете | Чем делать | Почему |
|---|---|---|
| Прямоугольник, полоса, градиент, круг | CSS (`kind: css`) | файл не нужен, масштабируется бесплатно |
| Иконка, логотип, пиктограмма | `figma_export kind: "svg"` | вектор, красится `currentColor` |
| Фото, иллюстрация, скриншот | `figma_export kind: "image"` | растровая заливка узла |
| Вектор с картинкой-заливкой, обрезка с поворотом, маска | `figma_export kind: "render"` | ни svg, ни image не отдадут результат |

> **Третий случай важен.** Пшеничная половина хиро — вектор с фигурным краем и картинкой внутри.
> Как `svg` он приходит без картинки, как `image` — прямоугольным кадром без фигурного края.
> Правильный ответ — `kind: "render"`. Пока это не выяснилось, хиро резался прямой вертикальной
> границей вместо кривой.

`kind: render` — **догадка, а не факт**: Figma не сообщает, что узел не выражается в SVG. У
каждой такой записи стоит `why` — прочитайте её, прежде чем тратить запрос, и не соглашайтесь
молча.

## 4.5 Иконки

```
figma_export(figma: [id конкретных узлов], kind: "svg")
```

- **Нужны id узлов, а не кадра.** Экспорт кадра в `svg` отдаст кадр целиком.
- **Скрытые слои.** Ответ «Failed to export node. This node may not have any visible layers»
  означает скрытый слой — повторить с показом скрытых. Не дорисовывать руками.
- **`monochrome: true` — обязательный `color` на обёртке.** Одноцветная иконка приходит с
  `currentColor`, и это правильно: цвет задаёт вёрстка. Но «задаёт» значит **задаёт**: без
  `color` на обёртке иконка наследует цвет текста и становится чёрной. Значение — поле `color`
  в той же записи ответа экспорта (или `color` у `svg` в `assets`). Многоцветные приходят со
  своими цветами; проверить, что они не потерялись.

> Все иконки двух блоков — зелёные и голубые в макете — ушли на сайт чёрными: ответ экспорта читали только ради путей к файлам, а поле `monochrome` пропускали.
> На скриншотах чёрные иконки были видны — сравнивали композицию, а не цвет.

- **Спрайт или инлайн.** Повторяющиеся иконки — в спрайт, одиночные и те, которым нужен
  `currentColor` или анимация, — инлайном.

## 4.6 Растровые картинки

```
figma_export(figma: [узлы], kind: "image", scale: 2)
```

- **Дедуп по содержимому.** 48 заливок свелись к 18 файлам; в `refs` перечислены все узлы, где
  картинка используется, — это сразу карта «какая картинка где».
- **`scaleMode`** (`FILL`, `STRETCH`, `FIT`) подсказывает `object-fit`.
- **Примечание про кадрирование.** «Кадрирование с поворотом не выражается без трансформации:
  отдано заполнение по cover» — значит, файл уже не совпадает с макетом пиксель в пиксель.
  Такие узлы инвентарь заранее помечает как `render`.
- **Переименовать при скачивании.** Экспорт отдаёт имена слоёв: `Rectangle 180`,
  `Снимок экрана (1) 1`, кириллица в URL. В проект они должны попасть как `doc-01.webp`,
  `hero-fields.webp`. Два узла с одинаковым именем и разным `scaleMode` — два разных файла:
  один такой перезаписал другой.

**Фон секции — картинка на всю высоту.** `backgrounds` у `figma_spec` перечисляет контейнеры с
заливкой-картинкой: прозрачность, цвет под ней и рамку. Такой фон тянется на всю высоту блока
и переносится вместе с прозрачностью, а не заменяется своим canvas на секцию: на стыках он
обрывался, затемнение героя кончалось за карточкой. Стыки сверяет `figma_compare` с
`sections: true` — поле `seams`.

**Трейс растра — растром.** Узел «Traced Image» или кадр с белой заливкой под вектором в svg
приезжает белым прямоугольником под путём: на тёмном фоне по краю белая кромка. `figma_spec`
отмечает такой узел `kind: render` с причиной, `figma_export kind: svg` — полем `warning`; нужен
svg — `dropBackground: true` снимет подложку.

## 4.7 Обработка

- **Рендер приходит PNG** — 3 МБ на одну фигуру. `image_convert` в WebP: стало 232 КБ с
  прозрачностью.
- **`width` и `height` на `<img>` обязательны** — иначе прыжок раскладки при загрузке.
  `layout_audit` ловит это как `imagesWithoutDimensions`.
- **`loading="lazy"`** всему, кроме первого экрана; первому экрану — `fetchpriority="high"`.

## 4.8 Краска узла ассетом не приезжает

**Обводка, тень и радиус живут на узле, а не в экспортированном файле.**

> Обложки документов приехали картинками, вставленными как `<img>`, — и потерялся
> `{stroke #d9d9d9 3}`, стоявший на узле-прямоугольнике. Картинка правильная, рамки нет. То же с
> карточками новостей: `Rectangle 218 {stroke #d9d9d9 3}`.

После вставки каждого ассета — посмотреть краску его узла в `figma_spec` или `figma_inspect`
с `mode: "outline"` и перенести в CSS.

## Известное расхождение моделей: обводка и `border-box`

Карточка 80px в макете даёт 83.52px в вёрстке. Разница — 2px рамки с каждой стороны: Figma не
считает обводку в высоту кадра, CSS при `box-sizing: border-box` считает.

Это системное расхождение моделей, а не дефект вёрстки. Чинится `outline` вместо `border`, но
ломает радиусы. Обычно правильное решение — оставить как есть и знать об этом, читая отчёт
сверки.

## 4.9 Шрифты

1. **Понять, что в макете.** Обычно коммерческий шрифт. Спросить у человека: есть ли файлы, чем
   заменять, если нет.
2. **Подмена меняет метрики.** Строки станут выше или ниже макетных, и страница поедет по
   высоте. Это ожидаемо и не дефект — но означает, что попиксельное сравнение на длинной
   странице бесполезно, а `heightNote` в отчётах сверки будет ненулевым всегда.
3. **CJK и другие большие наборы режутся по глифам.** Полный Noto Sans SC — 8.3 МБ. Сабсет по
   символам, реально встречающимся в проекте, — 174 КБ. Скрипт сабсета класть в репозиторий и
   перезапускать после правки текстов.
4. **`font-display: swap`** и явные `@font-face` только для используемых начертаний.

## 4.10 Покрытие глифов

Шрифт макета может не содержать нужного языка: бесплатный Bebas Neue в Google Fonts без кириллицы, хотя заголовки макета набраны им по-русски, а Figma молча показывает запасной. Проверка - fontkit `hasGlyphForCodePoint` по набору символов языка и валюты. На ТОПГАН в шрифте не было `₽`, и агент без вопроса выгрузил символ картинкой. Нет глифа - вопрос человеку. Варианты семейства в макете ("Bebas Neue Ru", "Bebas Neue Cyrillic") сводятся к одному семейству по начертанию.

## 4.11 Шкала между макетами

При двух макетах (380 и 1440) и масштабировании через vw мобильная вёрстка на планшете раздувается вдвое. Типовое решение - ограничить рост шкалы в мобильном диапазоне: `html { font-size: min(10 / 380 * 100vw, 12px) }` до десктопного брейкпоинта. Это вопрос человеку с готовым вариантом: своя шкала поверх шкалы фреймворка - отход от его модели.

## Гейт фазы

Заведены переменные и UI-кит: кнопки, ссылки, инпуты, карточки, таблицы. Ни одно значение из
`figma_tokens` не попало в вёрстку без подтверждения на конкретном узле; `parallels` учтены в
размерах компонентов. Все ассеты в проекте и подключены, ни одного дорисованного руками; у одноцветных иконок задан `color`, краска узлов перенесена в CSS. Шрифты подключены, покрытие глифов проверено, подмена согласована. UI-кит сверен на работающей странице.
