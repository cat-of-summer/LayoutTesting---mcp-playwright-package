# Фаза 10. Цикл блока

Главный раздел. Порядок внутри важен: сначала спецификация до листьев, потом структура, потом стили, потом сверка картинкой.

## Чек-лист

ВХОД: каркас готов, есть ref блока в каждом кадре (десктоп и мобильный).
ШАГИ:
  1. figma_spec(ref, depth ≥ 6) — до листовых векторов; unresolved в ответе пуст (иначе раскрыть).
  2. Для каждого TEXT — font, size, weight, line-height, color, ширина (fill/hug) из css; мелочь (тире, буллеты) отдельно.
  3. Для каждого VECTOR/ELLIPSE — заливка в CSS обёртки; svg с monochrome — color.
  4. Одинаковые соседи (×N в outline, parallels у figma_components) — сравнить y детей: фиксированные высоты.
  5. Мобильный узел блока — той же процедурой (шаги 1–4), не масштабированием десктопа.
  6. Структура из дерева; координаты вложенных контейнеров вычитать по обеим осям.
  7. Верстать: без px от ширины кадра, без cover вместо координат, состояние ≠ данные.
  8. computed_styles → правка доехала; нет — matched_rules.
  9. figma_compare mode: semantic — расхождения объяснены или исправлены (не «допуск»).
  10. figma_compare sections: true (или pixel по selector) — картинка с картинкой по каждой секции.
  11. layout_stress(widths из figma_sync.widths.suggested).
  12. Живая сессия: hover каждого интерактивного элемента, interaction_audit; silent пуст.
  13. Повторить 9–10 после правок; реестр блок → проверки.

## 10.1 Снять спецификацию — до листьев

```
figma_spec(узел блока, depth: 6..8)
```

Один вызов отдаёт всё: дерево слоёв с раскладкой и краской (`outline`), полные тексты (`text`),
стили (`css`) и список ассетов с тем, что каждому нужно (`assets`).

Краска приходит прямо в строке дерева:

```
751:2053 VECTOR "Vector 13" 0,71 557x0 {stroke #000000 5}
751:2021 RECTANGLE "Rectangle 174" -3,0 1471x920 [img] {img op0.7}
751:1907 RECTANGLE "Rectangle 180" 805,56 515x729 [img] {img, stroke #d9d9d9 3}
```

**Ни одно значение не берётся из рендера.** Рендер систематически врёт про толщины, цвета и
непрозрачность. У `LINE` высота рамки всегда 0 — толщина линии только в `stroke`.

**Строка «… N вложенных глубже depth» означает, что блок не разобран.** Листовые векторы —
тире, буллеты, разделители, иконки — пропадают первыми: они мелкие, лежат глубоко, и на общем
скриншоте их цвет не бросается в глаза. Ответ `figma_spec` сводит это в `unresolved`:
свёрнутые по глубине узлы, svg без цвета, несинхронизированные связи. Пока он не пуст, фаза
не закрыта.

> Тире подпунктов лежало во фрейме 14x14, свёрнутом на `depth: 4` («… 1 вложенных глубже»).
> Внутрь не пошли, цвет придумали. У текстового элемента должны быть видны все свойства сразу —
> это даёт `css`; для этого блока вызвали только `outline`.

Для каждого текстового узла — полный набор: `font-family`, `size`, `weight`, `line-height`,
`color`, ширина (`w:fill` / `w:hug`), выравнивание. Для каждого вектора и эллипса — заливка и
обводка, которые пойдут в CSS обёртки (`color` для `currentColor`).

Отдельно — то, что в одну декларацию не укладывается и потому легко теряется:

- `notes` у узла в разделе `css`: картинка с собственной прозрачностью — это отдельный слой, а не
  `background` с `opacity`; маска — `clip-path` на родителе;
- `effects` в `figma_tokens`: размытие, `backdrop`, режим наложения, полупрозрачная
  заливка-картинка. Порога частоты у них нет намеренно — они перечисляются, даже встретившись
  один раз. Токеном они не станут, но без них страница выходит ярче и резче макета.

### Одинаковые соседи — сравнивать вместе

Строка `×N как id` в outline и `parallels` у `figma_components` — это три инстанса, которые надо
смотреть **рядом**, а не по одному. Совпадает `y` дочернего узла при разной высоте соседа —
у соседа фиксированная высота, как бы он ни был помечен (`h:hug` при `270x66` — это 66px).

### Мобильный узел — той же процедурой

Мобильный кадр разбирается **блок за блоком**, шагами 1–4, а не «как десктоп, только уже».
Дизайнер на мобильной не масштабирует, а переставляет: карточки схемы на мобильной занимают
ширину экрана, а не уменьшены в 0.57 раза; шапка лежит отдельным кадром; слайдер становится
колонкой.

> Мобильный узел схемы той же ширины рамки, но другой высоты, прочли как «уменьшенная копия
> десктопного» и масштабировали композицию целиком. Внутрь мобильного узла не зашли ни разу.
> Другая высота при той же рамке уже говорила, что композиция другая.

## 10.2 Структура — из дерева, не из картинки

Порядок DOM = порядок чтения самой узкой вёрстки. Перестановки на широких экранах делаются CSS,
а не второй разметкой. Декор — псевдоэлементами и `absolute`, фоновый прямоугольник — фоном
контейнера, контент не позиционируется абсолютно.

> **Признак неверной структуры:** ритм приходится добивать магическими отступами. В блоке «медиа»
> были построены две независимые колонки по картинке, а потом подгонялись `margin-top: 149px` и
> `209px`. В дереве макета видео и тезис лежали **в одной строке** — после перестройки отступы
> стали не нужны.

**Координаты в `figma_inspect` — от рамки запрошенного узла.** Позиционируя ребёнка вложенного
контейнера, вычесть смещение контейнера по **обеим** осям: нижний ряд элементов схемы уехал на 32px
вправо, потому что `y` блока вычли, а `x` — нет. Пересчёт «в голове» при переносе чисел в
данные — то место, где это случается; сверка картинкой (10.5) — то место, где это ловится.

## 10.3 Верстать

Геометрию из макета не подменять «умными» приёмами. `object-fit: cover` вместо координат — это
отказ от макета в пользу догадки браузера: как только высота блока перестаёт быть макетной,
кадрирование уезжает.

Числа, посчитанные от ширины кадра, в вёрстку не попадают: `max-width: 1080px`, потому что «в
макете 1440 выглядит так», — привязка к одному экрану.

**Фиксированные px выше брейкпоинта при нефиксированном контейнере — запрет.** Слайдер 886px +
колонка 272px из макета 1440 на ширине 1068 требуют 1200px в контейнере 1028 — колонка уходит
за экран. Один брейкпоинт и фиксированные пиксели над ним — не адаптив: между макетными
ширинами — проценты, `clamp()`, `minmax()`, перенос.

**Состояние — не данные.** Раскрытая карточка в макете — это `hover` или активный слайд, а не
«у этой карточки есть суммы». Подгонять поведение под высоту секции нельзя.

## 10.4 Проверить, что правка доехала

```
computed_styles(селектор, одно характерное свойство)
```

Не совпало с файлом — `matched_rules` покажет победившее правило **с файлом и строкой**.
`overriddenByStand` в ответе значит, что значение перебито стендом в замороженной сессии
(`opacity`, `visibility`, `transform` у закреплённых по прокрутке элементов) — это не ваш CSS,
и в живой сессии его нет.

Что читать в ответе `browser_goto` при повторном переходе на тот же адрес:

- `reloaded: true` — кэш браузера снят целиком, вместе со стилями и скриптами;
- если после этого страница всё равно отдаёт старое, **старое отдаёт сервер**. Dev-сервер держит
  свой кэш трансформации, и ни сброс кэша браузера, ни `?v=<число>` его не трогают. Лечится
  перезапуском dev-сервера — по PID порта, а не `taskkill /IM node.exe` по всей машине;
- `retried: 1` — первая попытка упёрлась в отказ соединения, вторая прошла: сервер как раз
  поднимался;
- `recovered` — сессия стояла на странице-ошибке и вернулась этим переходом. Открывать новую
  сессию не надо: контекст, патчи и логин целы.

> **Зачем отдельный шаг.** Дважды dev-сервер отдавал старый CSS, и ошибку искали в коде, где её
> не было. `matched_rules` показал победившее правило с исходником — и стало видно, что в
> отданном CSS действительно лежит старая декларация.

## 10.5 Сверка с эталоном — картинка, а не высоты

```
figma_compare(sessionId, узел блока, mode: "semantic")     → тексты, кегли, paint
figma_compare(sessionId, кадр, sections: true)             → pixel по каждой секции
```

**«Высота секции совпала» — не критерий.** Он не видит цвет иконок, положение внутри строки,
выравнивание соседей, сдвиг ряда на 32px, мелкие элементы. Критерий — картинка с картинкой.
Порядок жёсткий:

1. `semantic` — и по каждому расхождению либо правка, либо объяснение с узлом (не «принял за
   допуск»);
2. `sections: true` — попиксельно по каждой секции кадра (или `mode: "pixel"` с `selector`);
   `diff` каждой секции просмотрен;
3. только после этого блок готов. `coverage` в ответе показывает, что для этого кадра ещё не
   запускалось.

> `pixel` не запустили ни разу: semantic-отчёт давал длинный список смещений, их объясняли
> переносами текста и «сойдётся семантика — тогда пиксели». В итоге ни одну секцию не сверили
> картинкой, и чёрные иконки, уехавший ряд элементов, плавающие даты и прижатые влево точки
> пагинации ушли в сдачу.

Читать **оба** раздела `semantic`-отчёта:

- **`semantic`** — тексты, кегли, межстрочные, цвет текста;
- **`paint`** — фон, рамки и их цвет, **толщина и длина линий**, радиусы, размер декора. Класс
  расхождений, которого в текстах не видно.

Четыре правила чтения:

1. `shiftedBlock` на N элементов — **одна** находка. Чинить высоту блока выше, а не двадцать
   элементов. Но «блок −50px» не отменяет мелких смещений внутри него — их разбирают после.
2. Расхождение до 1px и разница рендеринга шрифтов — не дефект.
3. **Отчёт урезан.** «Показано 6 из 135» значит, что 129 не проверены. Как дочитать — в `note`.
4. `unmatched` делится на две корзины, и это разные действия. `shifted` — узел на странице есть,
   и `off` показывает остаток смещения сверх уже применённой поправки: это работа. `notFound` —
   узла нет нигде; причину сверка не различает, потому что ходит по элементам: псевдоэлемент,
   внутренность SVG или правда не свёрстано.

> **Как урезанный отчёт подводит.** Ссылка, которая должна была быть синей, попала в свёрнутую
> группу `shiftedBlock` и в примеры не вывелась. Отчёт прочитали как «расхождений больше нет» и
> оставили чёрную.

> **Что даёт `paint` сверх текстов.** По ревью было сказано «толщина линии некорректная». Правка
> одного цвета закрыла бы вопрос неверно: `paint` показал, что расходится ещё и **длина** — 367px
> в макете против 666px в вёрстке. `border-bottom` так не ограничить — линия должна быть
> псевдоэлементом.

## 10.6 Стресс-тест блока — ширины между кадрами

```
layout_stress(sessionId, selectors: [селектор блока], widths: [из figma_sync.widths.suggested])
```

Сценарии: текст ×3, длинное слово без переносов, пустой текст, список из 12 и из одного,
вертикальная и битая картинка, набор ширин. Главная категория — `boxOverflow`: содержимое
вылезло за свой блок. Это **не то же самое**, что вылет за viewport, и обычный `layout_audit`
этого может не показать.

**Две точки — не адаптив.** Минимум: макетные ширины + 768, 1024, 1280 + минимальная ширина
между макетными. Планшетного макета нет — значит, между кадрами вёрстка проверяется, а не
пропускается.

> **Что нашлось только так.** На 320px бургер вылезал вправо на 12px, иконки подвала влево на
> 4px — собственные отрицательные `margin`, которыми добирали зону нажатия. На 376px было чисто.
> И шапка не переживала список из 12 пунктов меню. А на 1068px боковая колонка уходила за экран
> — проверяли только 1440 и 380.

## 10.7 Интерактив — замерить, а не посмотреть

```
browser_goto(..., animations: "allow")   — или живая сессия из фазы 0
interaction_audit(sessionId)
```

Прокликивает и наводит сам и отвечает, **что изменилось и за сколько**. Главное в ответе —
`silent`: элементы, не ответившие ничем. Стрелка слайдера, которая ничего не делает, — это ровно
`silent`, и на снимке она неотличима от рабочей.

Как читать `timing`:

- `smooth: false` — состояние переключилось за считанные кадры, то есть анимации на деле нет, как
  бы она ни была объявлена;
- `settled: false` с `kind: continuous` — бесконечная анимация: бегущая строка, спиннер. Это не
  дефект, и придуманной длительности у неё нет;
- `durationMs: 0` при работающем переходе значит, что меняется то, что этим способом не меряется:
  цвет, тень, фон. Не двигается и не гаснет — не измеряется.

Что прокликать обязательно: аккордеон (открыть, закрыть, переключить на другой), слайдер (обе
стрелки, до упора в обе стороны; **скриншот блока с пагинацией**, а не только `slideNext()`),
модалку (открыть, закрыть по фону, закрыть по Esc), форму (отправить, увидеть модалку успеха,
увидеть ошибку валидации), меню, выпадающие списки, табы. Навести на **каждый** элемент с
hover — в живой сессии, глазами по скриншоту.

> **Случай, который виден только замером.** В аккордеоне `grid-template-rows` тянулся 1000ms, а
> `min-height` переключался мгновенно: строка прыгала на полную высоту в первом кадре, и текст
> потом секунду разъезжался в готовой пустой коробке. На статичном снимке этого не видно вообще.

> **Почему замер, а не рассуждение.** Про слайдер было написано связное объяснение: «работает
> правильно, просто заблокирован — три карточки при трёх видимых». Проверка состояния изнутри
> показала `{ swiperExists: true, slides: 0 }` — Swiper не видел **ни одного** слайда.
> Правдоподобное рассуждение по классам в разметке — не диагноз.

> **Механика — не вид.** Точки пагинации проверили через `swiper.slideNext()` — переключение
> работало. Скриншот блока не сделали — и не увидели, что Swiper повесил на контейнер точек
> `position: absolute; left: 0`, и они прижаты к левому краю.

## Гейт блока

Пройдены 10.4–10.8 для десктопного и мобильного узла; `unresolved` пуст; расхождения либо
устранены, либо записаны с обоснованием и узлом; каждая секция сверена попиксельно; hover
каждого элемента просмотрен в живой сессии. Блок без прокликанного интерактива не считается
готовым, как бы точно он ни совпадал с макетом.

Вести реестр: блок → какие проверки пройдены. Иначе «кажется, проверял».
