# Фаза 3. Разбор комментариев

Каждый комментарий дизайнера становится проверяемым требованием с привязкой к секции.

## Чек-лист

ВХОД: реестр секций готов.
ШАГИ:
  1. figma_comments(все кадры) - один раз на проект: лимит 5 запросов в минуту общий. Нет REST - figma_status action: token, не вышло - блокер и вопрос человеку.
  2. docs/design/comments.md: комментарии по страницам и секциям, с id узла и эталонами анимаций.
  3. Каждое требование - пункт "- [ ]" с проверяемой формулировкой, а не пересказ.
  4. Ссылка на UI-кит или другую страницу - figma_find, затем figma_sync: снять сразу.
  5. Эталон на чужом сайте - открыть и посмотреть движение. Неясное - вопрос человеку.

## 3.1 Комментарий - это чек-лист

На приёмке ТОПГАН комментарий "затемнение у всех, hover убирает" применили не ко всем карточкам. Прочитанный комментарий без отметки о выполнении неотличим от забытого, поэтому у каждого есть строка:

```markdown
### hero (280:6100)
- [ ] Карточки затемнены все, hover убирает затемнение (280:6667). Эталон: animated-content.
- [ ] Цифры появляются по одной сверху вниз, после подписи.
```

Эти пункты переходят в микро-ТЗ страницы, и `page_ready` с `checklist` не отвечает `ready: true`, пока хоть один открыт.

## 3.2 Как читать комментарии

```
figma_comments(кадры)   → требования, которых нет в самом макете
figma_history(узел)     → что поменялось в макете за период (с прошлой сдачи), с diff: true — по полям
```

**Комментарии читаются до вёрстки.** Это единственный канал, где живут требования вроде «здесь
JS-анимация по ховеру, как на сайте-эталоне» или «этот блок пока не делаем». Инструмент работает
только через REST; нет токена — `figma_status` с `action: token`, и только если выпуск не удался,
это блокер, о котором спрашивают человека.

Комментарий, поставленный на кнопку, относится к кнопке, а не ко всему кадру: `figma_comments` по
кадру или блоку отдаёт и комментарии на его потомках (`on: descendant`, путь и ссылка на элемент).
`figma_inspect` и `figma_spec` показывают по узлу сводку `comments` — если там не ноль, прочитать
треды `figma_comments` по этому узлу до вёрстки блока.

> На одном лендинге `figma_comments` не вызывали ни разу — hover трёх блоков придумали сами, а в
> комментарии стоял эталон с готового сайта. На другом — «поправить отступ», «здесь будет
> форма» тоже жили только в комментариях.

Цветовое слово в треде — «зелёным», «фирменный» — `figma_comments` сопровождает `colorHint`: какие
цвета на деле стоят в состояниях макета. Слово дизайнера — не имя токена. Ссылка на состояние
«в UI-ките», которого нет среди снятых кадров, ищется `figma_find` по тексту или имени — по всем
страницам файла, с набором вариантов вокруг найденного.

## Гейт фазы

Комментарии прочитаны или их отсутствие согласовано; каждый разложен по секции и записан проверяемым пунктом; ссылки на другие страницы и UI-кит сняты.
