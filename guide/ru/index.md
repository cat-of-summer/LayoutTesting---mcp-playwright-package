# Регламент вёрстки по макету

Порядок работы: тринадцать фаз, которые проходят по очереди, а не читают целиком.

Регламент собран из разбора реальных ошибок — одиннадцати багов ревью одного лендинга и тех,
что нашлись инструментами после. Каждое правило подпёрто случаем, когда его нарушение стоило
переделки.

## Как с этим работать

Это процедура, а не справочник. Порядок такой:

1. Вызвать `help(guide: "setup")` — фазу 0.
2. Сделать то, что в ней написано.
3. Проверить **гейт** — условие в конце раздела, при котором фаза считается закрытой.
4. Гейт закрыт — вызвать следующую фазу, её имя стоит там же, в конце раздела.

Каждая фаза сама называет следующую, поэтому держать в голове весь список не нужно: достаточно
помнить, на какой вы сейчас.

Гейт — не формальность. Почти все дорогие переделки случались там, где фазу закрывали
«примерно»: не проверили связность стенда с проектом и потратили пять вызовов на диагностику
посреди вёрстки; не спросили про шрифты и переделали типографику; не прокликали слайдер и сдали
его сломанным.

Два раздела вне очереди, их читают в любой момент: `rules` — десять правил одной страницей,
`symptoms` — таблица «симптом → инструмент».

## Фазы целиком

Список нужен, только чтобы видеть масштаб работы. Проходить их по нему не надо — идите по
цепочке, каждая фаза приведёт к следующей.

| Раздел | Фаза | О чём |
|---|---|---|
| `setup` | 0 | стенд, связность с проектом, правила проекта |
| `frames` | 1 | разведка макета: какие кадры верстать |
| `inventory` | 2 | блоки, связи, типовые элементы |
| `system` | 3 | токены, компоненты, брейкпоинты |
| `assets` | 4 | иконки, картинки, краска узла |
| `fonts` | 5 | подмена, метрики, сабсеты |
| `content` | 6 | тексты в данные, артефакты переносов |
| `questions` | 7 | что спросить у человека до первой строки |
| `motion` | 8 | анимации и состояния элементов |
| `shell` | 9 | шапка, подвал, UI-кит |
| `block` | 10 | цикл блока — главный раздел |
| `page` | 11 | страница целиком |
| `project` | 12 | проект целиком и сборка |

## Чего здесь нет

Оговорок по конкретным инструментам: форма ответа, нюансы параметров, поддержка движками. Это
`help` с `tool: имя`. Регламент говорит, что делать; `help` — как устроен инструмент.
